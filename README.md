# Мой день — планировщик дня

Лёгкое PWA-приложение: задачи, тайм-блоки, привычки, неделя и итоги.
Работает на Mac и iPhone, офлайн, синхронизируется через Supabase.

Без сборки, без зависимостей, без фреймворков — только HTML, CSS и ванильный JS.
Ставится на GitHub Pages как есть.

---

## Что умеет

| Раздел | Возможности |
|---|---|
| **День** | задачи с приоритетом и оценкой времени, тайм-блоки (перетаскиваются мышью), таймер факта, повтор задачи, привычки на сегодня, опыт, итоги вечера |
| **Привычки** | недельная сетка Пн–Вс, отметки по дням, прогресс за неделю, стрики |
| **Неделя** | два масштаба: неделя (карточки с кольцами) и месяц (календарь 6×7) |
| **Итоги** | серия дней, лучшая серия, график за 14 дней, процент выполнения, заметка о дне |
| **Деньги** | доходы и расходы по категориям, остаток за месяц, разбивка по категориям, свои категории |
| **Ещё** | тема, напоминания, синхронизация, экспорт JSON и .ics, печать/PDF |

**Офлайн.** Всё лежит в `localStorage`, интерфейс кешируется service worker'ом.
Без сети приложение открывается и работает, изменения уходят в облако позже.

**Синхронизация.** Каждый день — отдельная запись. Слияние идёт **по задачам**:
у каждой свой `updatedAt`, удаления помечаются надгробием `removed[id]`.
Поэтому задача, удалённая на одном устройстве, не «воскресает» при синхронизации
с другим — раньше день выбирался целиком по времени и это было возможно.

**Отмена.** Удаление задачи показывает тост с кнопкой «Отменить» на 6 секунд.

**Факт и повтор.** У задачи можно запустить таймер — опыт пойдёт по фактическому времени,
а не по оценке. Повтор (ежедневно, по будням, еженедельно, ежемесячно) создаёт следующую
задачу автоматически при выполнении.

**Поиск и клавиши.** `/` или `Cmd+K` — поиск по всем дням. На компьютере: `N` — новая задача,
`←`/`→` — день, `T` — сегодня, `1`–`5` — разделы.

**Серии привычек.** У каждой привычки считается текущая серия (🔥 N) и рекорд.

**Вредные привычки** живут отдельным блоком на дне: только чекбоксы «было / нет».
Отметка = срыв и штраф к опыту (см. ниже).

**Вредные привычки.** В редакторе привычки есть тип: полезная или вредная. Отметка вредной —
это срыв, а не опыт: **−1 XP с общего уровня**, размазанный поровну по всем навыкам
(−1/N каждому). Опыт при этом не уходит в конкретный навык, поэтому селектор навыка
для вредной привычки скрыт. В недельной сетке срыв отмечается красным, а прогресс
считается как «чисто X%».

## Supabase: синхронизация между Mac и iPhone

1. Создай бесплатный проект на [supabase.com](https://supabase.com).
2. SQL Editor → New query → вставь содержимое `supabase.sql` → Run.
   Появится таблица `days` с открытой политикой для `anon`.
3. Возьми **Project URL** и **publishable key** (начинается с `sb_publishable_`).
   Подойдёт и legacy-ключ `anon` (начинается с `eyJ`). **Secret key (`sb_secret_`) в браузер вставлять нельзя** —
   приложение такой ключ отклонит.
4. В приложении: «Ещё» → «Синхронизация» → вставь URL и ключ → «Подключить».
5. Повтори п. 4 на втором устройстве. Поле **Пространство** должно совпадать
   (по умолчанию `personal`).

Готово: точка в приложении станет зелёной, дни начнут сходиться.

> Ключ хранится в `localStorage` браузера, а не в коде. Publishable-ключ публичен
> по своей природе: политика в `supabase.sql` открывает таблицу всем, кто знает
> URL и ключ. Для личного планировщика это приемлемо; для настоящей приватности
> включи Supabase Auth (magic link) и замени политику на `auth.uid() = user_id`.

## Вход по magic link (необязательно)

Закрывает таблицу от посторонних. Порядок важен.

1. Supabase → **Authentication → Providers → Email** — включён по умолчанию.
2. **Authentication → URL Configuration** → в **Redirect URLs** добавь
   `https://<user>.github.io/<repo>/` (и `http://127.0.0.1:8787/` для локальной отладки).
3. Выполни `supabase/auth.sql`. После этого аноним видит только «бесхозные» строки,
   а свои — только владелец.
4. В приложении: **Ещё → Аккаунт** → почта → «Отправить ссылку».
5. Открой письмо **в том же браузере** — приложение поймает токен из адреса,
   выполнит вход и заберёт старые дни через `claim_legacy_rows()`.
6. Повтори вход на втором устройстве с той же почтой.

Откат: снова выполнить `supabase.sql` (вернёт открытую политику для `anon`).

## Напоминания без push: подписка в Календаре

Самый простой путь — отдать задачи в iPhone-Календарь как подписной календарь.
Один раз добавляешь ссылку, дальше система сама хранит события и будит за 5 минут.

1. Dashboard → **Edge Functions** → создай функцию `calendar`, вставь код из
   `supabase/functions/calendar/index.ts`, **Verify JWT выключить** (Календарь не умеет
   передавать заголовки), Deploy.
2. В приложении: **Ещё → Данные → Подписка в Календаре → Скопировать**.
3. iPhone: **Настройки → Календарь → Учётные записи → Добавить учётную запись →
   Другое → Добавить подписной календарь** → вставить ссылку (или просто открыть
   `webcal://` на телефоне).

События обновляются по расписанию iOS (обычно раз в час-сутки), будильники работают
офлайн, потому что события уже лежат в Календаре. Для этого не нужны ни VAPID,
ни cron, ни service worker.

## Push при закрытом приложении

1. Выполни `supabase/push.sql` — появится таблица подписок.
2. Database → **Extensions** → включи `pg_cron` и `pg_net`.
3. Dashboard → **Edge Functions** → создай функцию `push-tick` и вставь код из
   `supabase/functions/push-tick/index.ts`. **Verify JWT оставь включённым** —
   ключ передаётся в заголовке `apikey`.
4. **Edge Functions → Secrets** добавь `VAPID_PUBLIC`, `VAPID_PRIVATE`,
   `VAPID_SUBJECT` (например `mailto:you@example.com`).
   Ключи сгенерированы один раз и лежат в `../vapid-keys/vapid.txt` рядом с проектом —
   приватный ключ в браузер и в репозиторий не попадает.
5. Выполни `supabase/push-cron.sql`, заменив `<PROJECT_REF>` — функция будет
   вызываться раз в минуту с заголовком `apikey`.
6. В приложении: **Ещё → Push** → включить. На iPhone сначала добавь приложение
   на «Домой» и открывай именно с иконки: push в Safari-вкладке iOS не работает.

Проверка: создай задачу со временем через 3–4 минуты, закрой приложение, дождись уведомления.

## Напоминания: честно о пределах iOS

Уведомления приходят, пока приложение открыто (на Mac и на iPhone).
Полноценные push-уведомления при закрытом приложении требуют серверной части
(VAPID + APNs) — в текущей версии их нет.

Рабочая альтернатива, которая есть уже сейчас:
«Ещё» → «Календарь» → скачать `.ics` на завтра → открыть в Календаре.
События встанут с будильником за 10 минут — это системные уведомления, они работают всегда.

## Опыт и навыки

Опыт считается из времени задачи: 1 час = 1 XP (45 минут = 0,75; 2,1 часа = 2,1).
Отметка привычки даёт 0,25 XP.

У каждой задачи и привычки есть **навык** (Готовка, Спорт, Работа, Учёба, Дом, Отдых, Разное —
список можно пополнять). Опыт идёт одновременно в навык и в общий уровень.

Уровни: 50 XP до второго, дальше +25 за уровень (2-й — 50, 3-й — 75, 4-й — 100…).

**Дизмораль.** Если навык не получал опыта 3 дня и больше, включается понижение:
−15% накопленного опыта навыка за каждый день простоя, но не больше 60%.
Два дня простоя — норма, штрафа нет. Опыт снижается и в навыке, и в общем уровне,
а при первом же занятии штраф снимается. Отключить нельзя.
При открытии приложения приходит уведомление (если разрешены системные), а в карточке опыта
висит красная плашка со списком простаивающих навыков.

## Доступность

Прошёл аудит по WCAG 2.2 AA (код + рантайм-замеры в WebKit). Что сделано:

- контраст текста ≥ 4.5:1 в обеих темах (токены `--ink-faint`, `--control-line` пересчитаны),
  границы инпутов ≥ 3:1, белый текст на фиолетовых кнопках ≥ 5.7:1;
- тап-цели: чекбокс задачи и точка синхронизации — 44×44 при сохранении визуального размера;
- шторка: доступное имя (`aria-labelledby`), `inert` на фоне, focus-trap, Escape, возврат фокуса;
- фокус не теряется при перерисовке списка (сохраняется по `data-fkey`);
- live-регион для смены дня, выполнения задачи, отметки привычки и статуса синхронизации;
- табы: `Home`/`End`, фокус переходит в панель, навигация идёт до контента в DOM;
- приоритет задачи виден не только цветом, но и текстом;
- `color-scheme` для нативных контролов, `prefers-reduced-motion` учитывается и в JS.

Что осталось: настоящий прогон VoiceOver на iPhone (аудит — это код и замеры, не скринридер-тест),
радиогруппа для выбора приоритета, list-семантика для привычек и недели.

## Проверки, которые уже прогнаны

- Рендер всех пяти экранов в WebKit на 390×844 и 1200×900 — без ошибок JS.
- Цикл синхронизации против мока Supabase: отправка изменений, получение чужой
  правки дня, слияние по `updatedAt`, повторный рендер.
- Офлайн-загрузка: приложение открывается без сети, состояние читается из `localStorage`.
- Код-ревью: гонки в очереди синхронизации, переход через полночь, блоки вне сетки дня.
- Доступность: контраст, тап-цели, фокус в динамике, имя диалога, `inert` фона (проверено рантаймом).
- Слияние по задачам: проверено, что удалённая задача не возвращается, а более новая версия побеждает.
- Отмена удаления: проверено в WebKit — задача возвращается на место, надгробие снимается.
